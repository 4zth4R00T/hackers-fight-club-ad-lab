# Шпаргалка ко дню 5: сеть

## Порты, которые будут встречаться постоянно

| Порт | Служба | Назначение |
|---|---|---|
| 53 | DNS | Преобразование имён в адреса |
| 80, 443 | HTTP, HTTPS | Веб |
| 88 | Kerberos | Проверка подлинности в домене |
| 110 | POP3 | Чтение почты |
| 25, 587 | SMTP | Отправка почты |
| 389, 636 | LDAP, LDAPS | Запросы к Active Directory |
| 445 | SMB | Файлы и принтеры |
| 3268 | Глобальный каталог | Поиск по всему лесу |
| 3389 | RDP | Удалённый рабочий стол |
| 5985 | WinRM | Удалённый PowerShell |

Если открыты порты 445, 3389, 389 и 88, перед вами Windows и домен.

## Диагностика

| Команда | Назначение |
|---|---|
| `ipconfig /all` | **Всё**: MAC, DNS, домен и суффиксы. Многое видно только здесь |
| `ipconfig /flushdns` | Очищает кэш имён |
| `ping host` | Проверяет, отвечает ли узел, хотя брандмауэр может блокировать ответ |
| `tracert host` | Маршрут по каждому переходу |
| `nslookup имя сервер` | Запрос к конкретному DNS-серверу |
| `netstat -ano` | Подключения и прослушиваемые порты с их PID |
| `arp -a` | Соседи в локальной сети |
| `route print` | Таблица маршрутизации |

## Разрешение имён по порядку

1. Кэш
2. Файл `hosts`
3. DNS

Когда DNS не отвечает, Windows «кричит» на всю сеть через LLMNR и NBT-NS, и именно здесь инструменты вроде Responder выдают себя за нужный узел. Поэтому эти протоколы отключают.

> Файл `hosts` не публикует записи SRV. Он подходит для отдельных имён, но не для поиска контроллера домена.

## Два ключа к Active Directory

**LDAP (389)** служит языком запросов к каталогу: любой `Get-ADUser` под капотом работает через LDAP. **Kerberos (88)** проверяет подлинность с помощью билетов: при входе вы получаете **TGT**, а для каждой службы обмениваете его на **TGS**. Ваш пароль по сети не передаётся.

```cmd
klist
```
